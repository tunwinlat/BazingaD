## 2024-03-14 - Sensitive Information Leakage in API
**Vulnerability:** The application was leaking potentially sensitive information back to the client via `error.message` on caught exceptions in API responses (e.g. `src/app/api/auth/login/route.ts` returning 500 status with `error.message`).
**Learning:** Returning `error.message` directly from catch blocks is a risky pattern as internal mechanisms (like database errors or unexpected exceptions) might throw errors containing sensitive details (e.g., query structure, internal paths, third-party responses). The application should always map unexpected errors to generic, safe error messages. Modifying `sameSite` policy or removing error messages from UI can lead to regressions, the goal is to sanitize the backend API responses.
**Prevention:** Always use generic fallback messages for unexpected exceptions (e.g. "Unknown error" or "Failed to perform action"). Avoid passing `error.message` directly to the client via API responses unless the error message is known to be sanitized and intended for public viewing (like custom validation errors).
